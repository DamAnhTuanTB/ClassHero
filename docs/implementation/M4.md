## M4: File upload, object storage và document processing

### M4.1: FilesModule và storage service

Mode: Worker/Integration

Mục tiêu:

- Có nền upload file vào object storage qua adapter S3-compatible.
- Local/dev dùng MinIO; staging/production dùng Cloudflare R2.

Phạm vi:

- Storage client/service dùng chung cho MinIO local và Cloudflare R2.
- File metadata create.
- Upload endpoint hoặc signed upload flow theo contract.
- Permission matrix theo `FilePurpose`.
- File type/size validation.

Done khi:

- Upload ảnh/PDF test lên MinIO local hoặc Cloudflare R2 được tùy `FILE_STORAGE_PROVIDER`.
- Metadata lưu DB.
- Không lưu file chính trên disk app.

### M4.2: Source document và lesson page mapping API

Mode: API only

Mục tiêu:

- Admin upload một PDF/tài liệu nguồn dài cho lộ trình, xử lý theo trang, rồi gán khoảng trang vào từng lesson.
- Vẫn hỗ trợ upload tài liệu lẻ trực tiếp vào lesson làm tài liệu bổ sung, nhưng flow tài liệu chính của MVP là source document dài + page range mapping.
- Chapter không có document/material riêng ở MVP; tài liệu học chi tiết chỉ gắn với lesson.

Phạm vi:

- Admin create/list/delete source document ở cấp learning path/course.
- Lưu metadata source document, source document pages và mapping `lesson -> page ranges`.
- Admin create/list/delete supplemental lesson document cho từng lesson.
- Admin upload/thay thế tài liệu gốc cho từng lesson: đổi page range từ source document hoặc upload một file riêng làm tài liệu chính của buổi.
- API validate page range: page tồn tại, `startPage <= endPage`, cảnh báo range trùng/bỏ sót nếu có.
- Khi admin xác nhận page range, tạo/cập nhật `lesson_documents` tương ứng với lesson và source document range.
- Tạo background job document processing/paid OCR artifact import cho source document.
- Tạo background job chunking cho lesson khi page range được tạo/sửa hoặc khi tài liệu bổ sung được upload.
- Job status trả qua `background_jobs`.

Done khi:

- Admin upload một PDF sách/giáo trình dài vào lộ trình.
- Hệ thống biết tổng số trang và tạo page records/status theo source document.
- Admin gán được page range cho từng lesson qua API.
- Mỗi lesson có `lesson_documents`/mapping đủ để worker chunk đúng nội dung theo `lesson_id`.
- Admin upload được tài liệu bổ sung riêng cho lesson và tài liệu đó cũng tạo job xử lý/chunk theo đúng `lesson_id`.
- Admin upload/thay thế được tài liệu gốc của một lesson mà không làm mất tài liệu bổ sung của lesson đó.

### M4.4: Paid OCR artifact và chunking

Mode: Worker/Integration

Mục tiêu:

- Xử lý PDF dài thành paid OCR artifact/page-level content, sau đó chunk theo từng lesson dựa trên page range đã được admin gán.
- Hỗ trợ cả PDF có text layer và PDF scan dạng ảnh.

Phạm vi:

- Paid OCR artifact/page-level processing trước khi chunk:
  - Tạo page record theo số trang của source document.
  - Tính `content_hash` của file gốc.
  - Dùng `pdf-parse` cho page count, metadata, thumbnail/preview và page image render khi cần.
  - Với tài liệu học chính, gửi file gốc lên paid OCR-first theo ADR-0007 hoặc import artifact đã cache.
  - Provider mặc định ban đầu là Mathpix; free OCR không phải production default.
  - Request và lưu OCR artifact đầy đủ nhất có thể: text, Mathpix Markdown/Markdown, LaTeX/math, tables, layout/line JSON, bounding boxes/regions, confidence, figures/diagrams/cropped images, page metadata.
  - Lưu metadata nguồn text: `paid_ocr`, provider/model/options, số trang OCR, lỗi OCR nếu có.
  - Lưu/copy Mathpix inline image/cropped image nếu provider trả về cho figures/diagrams/tables; không phụ thuộc lâu dài vào CDN/provider retention.
  - Giữ PDF gốc và khả năng render/crop page image fallback để phục vụ preview và visual Q&A khi provider không trả crop phù hợp; OCR text không thay thế hình gốc.
- Chấm chất lượng text theo trang/chunk candidate: quá ít text, nhiều ký tự rác, công thức/toán bị vỡ hoặc trang có ảnh lớn nhưng text ít.
- Chunking chỉ chạy sau khi có mapping `lesson_id -> page ranges`.
- Tài liệu bổ sung upload trực tiếp cho lesson dùng cùng pipeline OCR artifact/chunk riêng nhưng vẫn lưu chunks với cùng `lesson_id`.
- Lưu `document_chunks` không embedding hoặc embedding null.
- Khi admin sửa page range, xóa/tạo lại chunks của lesson liên quan và đánh dấu embedding/explanation cũ stale nếu có.
- Lưu error nếu OCR artifact import hoặc chunking thất bại.

Done khi:

- PDF dài tạo được page text và page status từ paid OCR artifact hoặc provider paid.
- PDF scan dạng ảnh cũng tạo được page text bằng paid OCR, hoặc job fail rõ lý do nếu provider/config lỗi.
- Sau khi có page range mapping, chunks được tạo theo đúng `lesson_id`.
- Tài liệu bổ sung của lesson tạo được chunks bổ sung theo đúng `lesson_id`.
- Chunk có metadata source document, page start/end, page text source, layout/region refs và quality nếu có thể.
- Có thumbnail/page image reference, provider crop reference nếu có, hoặc khả năng render on demand từ PDF gốc cho từng trang.

### M4.5: Lesson document upload UI/status

Mode: UI + API

Mục tiêu:

- Admin có UI upload/quản lý một tài liệu nguồn dài cho lộ trình, gán khoảng trang vào từng lesson và xem trạng thái xử lý.
- UI không tạo upload tài liệu ở cấp chapter.

Phạm vi:

- FileUploader cho PDF/tài liệu nguồn dài ở cấp lộ trình/course detail.
- Source document detail/status: tổng số trang, trạng thái paid OCR artifact từng trang, lỗi trang nếu có.
- Nút `Chạy OCR` hiển thị provider/cost estimate và gọi Mathpix trên file gốc.
- Màn gán trang: danh sách lesson đã tạo, mỗi dòng có `fromPage`/`toPage`, preview thumbnail/text ngắn và warning range trùng/bỏ sót.
- Mỗi lesson row có hai action riêng: `Upload/Thay thế tài liệu gốc` và `Upload tài liệu bổ sung`.
- Khi admin lưu mapping, UI hiển thị trạng thái chunking/ready/failed theo từng lesson.
- Tài liệu bổ sung theo lesson: mỗi lesson luôn có khu vực/nút `Upload tài liệu bổ sung` riêng sau khi đã có hoặc chưa có page range.
- Upload lẻ từng lesson là supplemental document flow; không thay thế source document/page range flow cho tài liệu chính.
- Hiển thị job status từ `background_jobs`.
- Empty/error/loading state cho upload và processing.
- Không đặt upload tài liệu trong modal tạo lesson ở MVP.
- Không làm bulk upload nhiều file rồi map file vào lesson trong MVP; source document flow chỉ upload một tài liệu dài rồi map page range.
- Không làm embedding UI; embedding thuộc `M5.x`.

Done khi:

- Admin upload một PDF dài ở cấp lộ trình/course detail.
- Admin gán page range cho từng buổi học bằng UI.
- Admin upload/thay thế tài liệu gốc của một buổi học từ chính lesson row.
- Admin upload thêm được tài liệu bổ sung cho một lesson bằng nút riêng và thấy trạng thái xử lý riêng của tài liệu đó.
- Admin thấy trạng thái paid OCR artifact/page-level, chunking theo lesson và processing của supplemental documents.
- UI dùng API/file permission từ `M4.1` và `M4.2`.
