## M6: Quiz, flashcard, test CRUD thủ công

Ghi chú chung:

- CRUD trong M6 áp dụng cho cả nội dung admin tự tạo bằng tay và nội dung AI sinh ra ở M9.3 sau khi đã lưu vào cùng bảng quiz/flashcard/test.
- Nội dung AI sinh ra không phải artifact bất biến riêng; admin phải sửa,
  ẩn/hiện hoặc điều chỉnh từng set/item bằng cùng màn/API quản trị. Riêng action
  xóa cả Quiz set là xóa cứng và không thể khôi phục; câu Quiz lẻ, Flashcard và
  Test giữ policy xóa hiện hành cho đến khi có quyết định riêng.
- UI quản trị quiz/flashcard/test của M6 đặt trong màn chi tiết buổi học admin `/admin/lessons/[lessonId]`. Nếu màn này chưa tồn tại trong code, task UI đầu tiên của M6 phải tạo shell màn chi tiết buổi học trước: breadcrumb quay lại lộ trình, metadata buổi học, trạng thái tài liệu/OCR/chunk của buổi đó và các tab/section Summary, Quiz, Flashcard, Test, Documents.
- M6 chỉ làm CRUD/manual management và nơi review/sửa/xóa nội dung đã lưu. Nút sinh bằng AI có thể để chỗ nhưng không được active giả; action generate thật thuộc M9.8 sau khi M5/M9.1/M9.3 sẵn sàng.

### M6.1: Rich text JSON và shared content schema

Mode: API only

Mục tiêu:

- Chuẩn hóa dữ liệu rich text/công thức dùng chung.

Phạm vi:

- Shared schema cho Tiptap JSON nếu cần.
- DTO validation cho question/answer/explanation/hint.
- Support node format, list, text alignment, image reference và
  LaTeX/KaTeX/mhchem ở dạng data. Editor quản trị đầy đủ thuộc `M6.2`.

Done khi:

- Backend validate được content JSON.
- Frontend có helper render cơ bản nếu làm UI.

### M6.2: Quiz CRUD API và admin UI tối thiểu

Mode: UI + API

Mục tiêu:

- Admin quản lý quiz thủ công.

Phạm vi:

- CRUD quiz set.
- Xóa cả Quiz set là hard delete trong transaction, gồm câu hỏi, lời giải, hình,
  mọi Quiz attempt/answer phụ thuộc và delivery file hình đã hết tham chiếu; object
  MinIO/R2 cùng metadata file được dọn, audit log không bị xóa.
- CRUD quiz question item-level.
- Admin có thể duyệt từng câu AI hoặc duyệt tất cả câu AI đang chờ trong từng
  Quiz set; bulk review không tự lưu/phát hành cho học sinh.
- Câu có `sourceMetadataJson.aiGenerationId` được nhận diện là câu AI ở cả ô số
  điều hướng và card nội dung; card có action duyệt riêng từng câu. Câu admin
  tạo thủ công không hiển thị nhãn hoặc action AI.
- Question type gồm bốn lựa chọn: multiple choice, true/false một boolean,
  true/false nhiều mệnh đề và text input.
- Difficulty chỉ thuộc từng câu hỏi; quiz set không có field mức độ.
- Backend tự chấm tương đương cho text input, không yêu cầu admin cấu hình.
- Các quiz set hiển thị dưới dạng tab; chọn tab nào thì hiển thị toàn bộ câu hỏi của set đó ngay bên dưới.
- Hai icon câu trước/câu tiếp theo trong card Quiz chỉ thay nội dung câu đang
  xem và phải giữ nguyên tọa độ cuộn của trang; không chuyển focus lên thanh số
  câu khiến viewport tự cuộn.
- Khi tab Quiz đang active, `ArrowLeft`/`ArrowRight` trên bàn phím chuyển câu
  trước/câu tiếp theo, kể cả focus đang ở tab Quiz; không được đổi sang tab
  Kiến thức hoặc Flashcard. Không bắt shortcut khi đang nhập liệu hoặc mở dialog.
- Tab Quiz giữ đúng thứ tự tạo tăng dần: bộ tạo trước đứng trước, bộ tạo sau
  đứng sau; tạo thành công tự động chọn tab của bộ vừa tạo.
- Modal tạo quiz set điền sẵn tên tuần tự `Bộ câu hỏi N`; panel của set đang chọn
  có action sửa tên bằng cùng modal. Modal và panel không hiển thị mức độ cấp bộ.
- Form tạo/sửa câu hỏi hỗ trợ đầy đủ nội dung, loại câu hỏi, mức độ, đáp án đúng, gợi ý và lời giải chi tiết.
- Câu hỏi, từng phương án, gợi ý và lời giải dùng cùng rich editor Tiptap:
  bôi chọn văn bản để định dạng đậm/nghiêng/gạch chân/gạch ngang/đổi màu;
  bullet/danh sách đánh số; căn trái/giữa/phải/đều; `Tab`/`Shift + Tab` để
  tăng/giảm cấp thụt đoạn hoặc cấp danh sách; chèn ảnh `QUESTION_IMAGE`;
  chèn/sửa công thức Toán/Lý bằng LaTeX và Hóa bằng mhchem.
- Icon chèn bảng mở modal cấu hình hàng/cột/header; editor kéo resize cột bằng
  biên dọc và resize hàng bằng biên ngang, hỗ trợ header row/column,
  add/delete row/column, merge/split cell và xóa bảng. Các lệnh ngữ cảnh dùng
  toolbar icon có tooltip tức thì thay vì dãy nút chữ dài; table node rỗng chữ
  vẫn được frontend/backend coi là nội dung cấu trúc hợp lệ.
- Ảnh upload qua file storage hiện có; Tiptap image node giữ `fileId`, `src`,
  `alt`, alignment trái/giữa/phải, kích thước theo phần trăm và crop bốn cạnh
  không phá hủy file gốc; editor có resize handle, khung crop lưới một phần ba
  kéo trực tiếp trên ảnh và nút xóa nhanh, không nhúng base64 vào JSON. Ảnh mới
  giữ tỉ lệ rộng/cao gốc, dùng khung cơ sở bằng 60% chiều rộng editor nhưng mức
  resize ban đầu hiển thị là 100%; chỉ thay đổi phần trăm sau khi admin resize
  trong khoảng 20–100%.
- Với `TEXT_INPUT`, admin chỉ nhập một chuỗi đáp án canonical; UI không có action
  thêm/xóa biến thể, không hiển thị checkbox phân biệt hoa/thường hoặc yêu cầu
  khớp toàn bộ, nhưng vẫn có công cụ chèn/xem trước LaTeX/mhchem.
- Backend tự thử so sánh giá trị số chính xác trước để chấp nhận các dạng tương
  đương như `0.5`, `0,5`, `1/2`, `2/4`, rồi mới fallback về chuỗi đã chuẩn hóa
  Unicode/khoảng trắng và không phân biệt hoa thường. Giá trị số khác như
  `0.51` không được chấp nhận cho đáp án chuẩn `0.5`.
- Với multiple choice, admin thêm/xóa danh sách phương án động, tối thiểu 2 phương án và không giới hạn cố định ở 4 phương án.
- Với `TRUE_FALSE`, `correctAnswerJson` là một boolean chung; form render một
  cặp lựa chọn Đúng/Sai cho toàn câu.
- Với `MULTI_STATEMENT_TRUE_FALSE`, `questionJson` là đề dẫn chung;
  `optionsJson` là danh sách động tối thiểu 2 mệnh đề có ID duy nhất và rich
  content; `correctAnswerJson` ánh xạ mỗi `statementId` tới một boolean. Form
  cho thêm/xóa mệnh đề và chọn Đúng/Sai riêng trên từng dòng.

Done khi:

- Admin tạo/sửa/xóa câu quiz lẻ.
- Admin xóa cả Quiz set vĩnh viễn; API không ghi `deletedAt` cho thao tác này và
  không để FK phụ thuộc chặn việc xóa.
- Admin tạo/sửa câu `TEXT_INPUT` với đúng một đáp án canonical; modal không còn
  danh sách biến thể/cờ so khớp và backend chấp nhận các biểu diễn số tương đương
  nhưng từ chối giá trị số khác.
- Admin duyệt được riêng từng câu Quiz do AI tạo mà không duyệt các câu khác
  trong cùng bộ.
- Admin tạo được câu multiple choice có 2, 3, 4, 5 hoặc nhiều phương án hơn; đáp án đúng luôn ánh xạ tới một phương án còn tồn tại.
- Admin tạo/sửa được cả câu `TRUE_FALSE` một boolean và
  `MULTI_STATEMENT_TRUE_FALSE` nhiều mệnh đề; hai loại không ghi đè dữ liệu của
  nhau.
- Gợi ý và lời giải chi tiết được lưu thật, đọc lại được khi mở form sửa.
- Điều hướng câu trước/câu tiếp theo trong card Quiz giữ nguyên vị trí cuộn hiện
  tại sau khi câu mới render.
- `ArrowLeft`/`ArrowRight` trên màn Quiz chuyển câu và giữ nguyên tab Quiz; các
  vùng nhập liệu/dialog vẫn giữ hành vi bàn phím riêng.
- Rich content mở lại giữ nguyên format, list, alignment, indentation,
  màu, cấu trúc/size/merge của bảng, alignment/kích thước/vùng crop ảnh và
  công thức;
  phương án chỉ chứa công thức hoặc ảnh có `alt` vẫn được xem là hợp lệ.
- Student đọc được quiz metadata/content.
- Quiz chỉ gắn với lesson, không gắn với chapter.

### M6.3: Flashcard CRUD API và admin UI tối thiểu

Mode: UI + API

Mục tiêu:

- Admin quản lý flashcard thủ công.

Phạm vi:

- CRUD flashcard set.
- CRUD flashcard item-level.
- Front/back/lời giải chi tiết/difficulty; form không còn ô gợi ý.
- Lời giải chi tiết thủ công dùng `ai_explanations` với
  `targetType=FLASHCARD`, `source=ADMIN`.
- Admin UI tối thiểu.
- Modal tạo flashcard set điền sẵn tên tuần tự `Bộ flashcard N`, lấy số lớn
  nhất đang có trong lesson rồi tăng một.
- Tab Flashcard giữ đúng thứ tự tạo tăng dần và tự động chọn bộ vừa tạo sau khi
  lưu thành công.

Done khi:

- Admin tạo nhiều bộ flashcard trong một lesson.
- Student đọc được flashcard content.
- Flashcard chỉ gắn với lesson, không gắn với chapter.

### M6.4: Test CRUD API và admin UI tối thiểu

Mode: UI + API

Mục tiêu:

- Admin quản lý bài kiểm tra thủ công.

Phạm vi:

- CRUD test set.
- CRUD test question item-level.
- Câu Test do AI tạo dùng cùng nhãn nguồn và action duyệt item-level như Quiz;
  câu admin tạo thủ công không hiển thị nhãn AI.
- UI/API câu hỏi tái sử dụng flow Quiz `M6.2` cho rich editor, bốn loại câu hỏi
  `MULTIPLE_CHOICE`, `TRUE_FALSE`, `MULTI_STATEMENT_TRUE_FALSE`, `TEXT_INPUT`,
  gợi ý, lời giải, validation, tab set và action sửa/xóa.
- Select `Loại câu hỏi` của Test hiển thị bốn lựa chọn tương ứng:
  `Trắc nghiệm`, `Đúng/Sai`, `Đúng/Sai nhiều mệnh đề`, `Nhập đáp án`.
- Modal tạo/sửa bộ đề giống modal bộ câu hỏi Quiz, bổ sung duy nhất field thời gian
  làm bài theo phút; API lưu `durationSeconds`.
- Tab Test giữ đúng thứ tự tạo tăng dần và tự động chọn bộ đề vừa tạo sau khi
  lưu thành công.
- Difficulty ratio metadata.
- Total score 10.
- Points default equal nếu chưa set.
- Admin UI tối thiểu.

Done khi:

- Admin tạo nhiều bộ đề trong một lesson.
- Admin duyệt được riêng từng câu Test do AI tạo.
- Admin tạo/sửa bộ đề với thời gian làm bài hợp lệ.
- Admin tạo/sửa được cả câu Đúng/Sai cũ với một boolean và câu Đúng/Sai nhiều
  mệnh đề; mọi mệnh đề của loại mới đều có đúng một đáp án Đúng/Sai và mở lại
  form không mất nội dung/ánh xạ.
- Câu hỏi có correct answer và grading config.
- Các câu chưa đặt điểm riêng được service chia đều để tổng điểm hiệu lực là 10.
- Test chỉ gắn với lesson, không gắn với chapter.

### M6.5: Student read-only lesson content API

Mode: API only

Mục tiêu:

- Student có thể load nội dung lesson để chuẩn bị flow học.

Phạm vi:

- Read lesson summary/materials/quiz sets/flashcard sets/test metadata.
- Enforce preview rule: trước ngày mở bài thi vẫn xem video/tài liệu/tóm tắt/quiz/flashcard, chưa làm test.

- Test availability không bị mở sai.

### M6.6: Test Admin dùng chung Quiz/Assessment core

Mode: Full-stack (UI + API + DB + Worker/Integration)

Mục tiêu:

- Chấm dứt implementation admin Test độc lập. Test Admin là mode `TEST` của
  cùng Assessment/Quiz admin core; khác biệt cấu hình duy nhất ở set editor là
  thời gian làm bài.

Phạm vi:

- Các route Test tương thích vẫn giữ prefix `/admin/test-*`, nhưng controller
  chỉ truyền kind `TEST` vào shared `AssessmentAdminService`; CRUD set/question,
  review từng câu/bulk review, generation JSON, publish/review, figure và
  solution refinement dùng cùng logic/component/hook Quiz.
- Modal tạo/sửa TestSet dùng cùng modal QuizSet và chỉ thêm `durationSeconds`
  (UI nhập phút). Không có difficulty ratio, total score hay points là input
  riêng của admin Test trong luồng mới.
- Modal AI Test dùng đúng UI/contract Quiz generation v2, target tùy chọn là
  `targetTestSetId`. Khi lesson chưa có TestSet, backend tự tạo `Bộ đề 1` với
  thời gian mặc định 15 phút. **Không có field duration, không gửi duration từ
  client và không dùng duration trong prompt**; backend đọc duration của
  TestSet đích hoặc dùng mặc định cho bộ đầu tiên khi cần snapshot/metadata.
- `quiz_figures` mở rộng target kép `quiz_question_id XOR test_question_id` để
  Test dùng cùng lifecycle revision/render/refinement; migration chỉ mở rộng
  figure target, không gộp bảng Quiz/Test hoặc thay đổi attempt học sinh.
- Worker generation/refinement/figure nhận target kind `QUIZ | TEST`, giữ
  `AiGenerationType.TEST` cho routing, usage và accounting, đồng thời dùng
  versioned Quiz/Assessment pipeline chung. Legacy Test jobs được phép hoàn tất
  trong cửa sổ cutover.
- Chống trùng Test dùng nguyên query/serializer/prompt contract của Quiz cho mọi
  câu Quiz còn tồn tại trong lesson, rồi nối thêm mọi câu Test còn tồn tại; cả
  hai tập đều không lọc theo review status và đều loại câu/set đã xóa mềm. Quiz
  generation vẫn chỉ đối chiếu câu Quiz.
- Quiz/Test dùng chung state machine `SAVE/PUBLISH/WITHDRAW`, review từng
  câu/hàng loạt và figure enrichment. `test_questions.published_at` giữ cùng
  watermark contract Quiz; duyệt câu cuối không tự phát hành TestSet.

Done khi:

- Mọi capability Admin Quiz hiện có đều xuất hiện và chạy cho Test bằng shared
  implementation; không còn API client/hook/schema/dialog/CRUD service Test
  admin độc lập.
- Modal tạo/sửa TestSet chỉ khác QuizSet ở thời gian làm bài; modal AI Test
  giống hệt modal AI Quiz và không có/không gửi duration.
- Khi chưa có TestSet, nút bắt đầu tạo AI vẫn hoạt động và tạo `Bộ đề 1` với
  thời gian mặc định 15 phút trước khi enqueue.
- Preview/enqueue Test đưa cả câu Quiz và câu Test hiện có vào cùng index chống
  trùng; câu chưa duyệt vẫn phải được đối chiếu.
- API Test legacy vẫn tương thích, Test figure/refinement/generation JSON dùng
  cùng core, và migration XOR bảo vệ đúng một target figure.
- Student Test attempt, timer, score, prerequisite và completion giữ behavior
  M7 hiện hành; M6.6 không biến Test thành runner Quiz hoặc gộp bảng attempt.
- Start Test chỉ trả hình đề; hình lời giải, đáp án và explanation chỉ xuất hiện
  ở review sau khi attempt đã nộp/chấm.
