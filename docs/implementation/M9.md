### M9.4: Student request-new reserve-first flow

Mode: UI + API

Mục tiêu:

- Student lấy bộ mới từ kho dự phòng, hết mới gọi AI.

Phạm vi:

- Request-new quiz/flashcard/test.
- Nếu có set dự phòng phù hợp: trả 200 EXISTING.
- Nếu hết: enqueue AI job, trả 202 QUEUED.
- Bộ mới lưu DB và trở thành dự phòng cho học sinh khác.
- Nối các action học sinh hiện có `Làm bộ Quiz mới`, `Học bộ Flashcard mới` và
  `Làm bài thi mới` vào endpoint request-new tương ứng; bỏ logic quay vòng local
  sau khi kết nối API thật.
- Với `200 EXISTING`, chuyển ngay sang set được cấp và mở đúng runner/session.
- Với `202 QUEUED`, hiển thị trạng thái đang tạo, polling job, khóa gửi lặp và
  tự refresh/mở set khi job thành công.
- Có loading, queued/running, error, retry và disabled state rõ ràng trên cả
  mobile/desktop, light/dark.

Done khi:

- Không gọi AI nếu còn bộ dự phòng.
- Response 200/202 đúng contract.
- Học sinh bấm được toàn bộ flow request-new của Quiz, Flashcard và Test từ UI;
  không cần dùng Swagger/curl để xác nhận tính năng chính.
- UI không âm thầm quay vòng về set cũ khi API đang queued hoặc lỗi.

### M9.5: AI explanation cache inline

Mode: UI + API

Mục tiêu:

- “Giải thích cho tôi” dùng cache ở cấp item.

Phạm vi:

- Endpoint explanation cho quiz/flashcard/test question.
- Với test question chỉ hiện sau submit.
- Cache hit trả 200.
- Cache missing/stale trả 202 job.
- Hash/stale logic theo target/source context.
- Thêm action `Giải thích cho tôi` tại quiz question, flashcard và test question;
  với test chỉ hiện sau submit.
- Cache hit hiển thị lời giải inline ngay; cache miss/stale hiển thị trạng thái
  đang tạo và polling đến khi có kết quả.
- Có loading, error, retry, disabled state và chống gửi lặp trên mobile/desktop,
  light/dark.
- Sau khi có lời giải, hiển thị `Chat thêm với AI` để bàn giao target item và
  lời giải đã lưu sang chat panel của `M9.6`; M9.5 không tự triển khai chat.

Done khi:

- Cùng item không gọi AI lại nếu cache còn hợp lệ.
- Nội dung thay đổi làm stale explanation.
- Học sinh bấm xem được lời giải inline trọn flow từ UI cho Quiz, Flashcard và
  Test; riêng Test chỉ cho phép sau submit. Flow bao gồm cache hit, queued,
  error và retry.

### M9.6: Chat AI trong lesson bằng RAG

Mode: UI + API

Mục tiêu:

- Student chat với AI theo tài liệu buổi học.
- Chapter chỉ là metadata tổng quan, không có context RAG riêng ở MVP.

Phạm vi:

- Chat session/messages.
- Retrieval theo lesson.
- Gửi một số tin nhắn gần nhất, không gửi toàn bộ lịch sử.
- Nhận target item và lời giải đã lưu khi học sinh đi từ action
  `Chat thêm với AI` của `M9.5`, đồng thời vẫn hỗ trợ mở chat trực tiếp từ lesson.
- Không cho học sinh upload ảnh/file trong chat.
- User-upload trong chat nếu làm ở version sau phải là chat attachment riêng, lưu object storage theo user/session/message với quota/rate limit/quyền truy cập riêng; không đưa vào OCR artifact cache của tài liệu nguồn.
- Nếu học sinh hỏi về hình/bảng/sơ đồ/trang cụ thể trong lesson, backend có thể tự lấy page image/crop từ PDF gốc làm visual context cho model vision theo budget/rate limit.
- Khi học sinh hỏi theo số trang in, backend phải resolve qua `printedPage` trong page metadata/image manifest trước khi chọn PDF page/crop. Nếu mapping thiếu hoặc mơ hồ, trả fallback rõ ràng hoặc hỏi lại.
- Từ chối câu hỏi ngoài phạm vi lesson.

Done khi:

- Chat lưu lịch sử.
- AI không trả lời ngoài context lesson.
- Câu hỏi về hình/trang trong tài liệu có đường lấy visual context từ PDF gốc hoặc fallback rõ ràng nếu chưa bật visual model.
