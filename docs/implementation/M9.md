## M9: AI generation, explanation và chat

### M9.1: AiModule structured output foundation

Mode: Worker/Integration

Mục tiêu:

- Chuẩn hóa gọi AI cho structured output.

Phạm vi:

- AiModule.
- OpenAI structured output provider.
- Gemini provider placeholder nếu cần.
- Zod/JSON Schema validation.
- AI generation logs.
- Background job lifecycle cho AI.

Done khi:

- AI call đi qua AiProvider abstraction.
- Output invalid không được lưu DB.

### M9.2: Admin generate lesson summary

Mode: Worker/Integration

Mục tiêu:

- Admin dùng AI tạo tóm tắt bài học.
- Summary AI chỉ tạo cho lesson, không tạo ở cấp chapter.

Phạm vi:

- API enqueue generate summary.
- Worker lấy context lesson document chunks.
- Validate output.
- Upsert `lesson_summaries`.
- Admin có thể sửa lại summary sau khi AI tạo.

Done khi:

- Summary tạo được từ tài liệu lesson.
- Không gửi toàn bộ PDF raw vào prompt.

### M9.3: Admin generate quiz/flashcard/test

Mode: Worker/Integration

Mục tiêu:

- Admin dùng AI tạo nội dung học tập.

Phạm vi:

- Generate quiz set/questions.
- Generate flashcard set/cards.
- Generate test set/questions.
- Mỗi lần generate nhận `lessonId` và chỉ dùng OCR chunks của đúng buổi học đó: page range source document đã gán cho lesson và supplemental documents thuộc lesson.
- Không dùng context toàn bộ sách, toàn bộ lộ trình hoặc lesson khác để sinh quiz/flashcard/test.
- Generated quiz/flashcard/test phải bám kiến thức trong lesson chunks nhưng không copy nguyên văn bài tập/ví dụ từ tài liệu nguồn.
- Lưu source chunk/page metadata để admin review/debug và report sai câu, không dùng metadata này như lý do sao chép nội dung.
- Save source AI và review status.
- Lưu output vào cùng quiz/flashcard/test set/item schema của M6 để admin dùng cùng CRUD sửa/xóa/ẩn/duyệt sau khi AI sinh.
- Quiz/Test generation phân biệt `TRUE_FALSE` một boolean và
  `MULTI_STATEMENT_TRUE_FALSE` nhiều mệnh đề; validate đúng shape của từng loại
  trước khi lưu.
- Mapping explanation nếu AI output có lời giải.

Done khi:

- Admin tạo được bộ AI và sửa/xóa/ẩn/duyệt được sau đó qua cùng flow quản trị M6.
- AI output được validate trước khi lưu.
- Output có guard chống trùng nguyên văn quá giống với bài tập/ví dụ trong context.

### M9.4: Student request-new reserve-first flow

Mode: Worker/Integration

Mục tiêu:

- Student lấy bộ mới từ kho dự phòng, hết mới gọi AI.

Phạm vi:

- Request-new quiz/flashcard/test.
- Nếu có set dự phòng phù hợp: trả 200 EXISTING.
- Nếu hết: enqueue AI job, trả 202 QUEUED.
- Bộ mới lưu DB và trở thành dự phòng cho học sinh khác.

Done khi:

- Không gọi AI nếu còn bộ dự phòng.
- Response 200/202 đúng contract.

### M9.5: AI explanation cache inline

Mode: Worker/Integration

Mục tiêu:

- “Giải thích cho tôi” dùng cache ở cấp item.

Phạm vi:

- Endpoint explanation cho quiz/flashcard/test question.
- Với test question chỉ hiện sau submit.
- Cache hit trả 200.
- Cache missing/stale trả 202 job.
- Hash/stale logic theo target/source context.

Done khi:

- Cùng item không gọi AI lại nếu cache còn hợp lệ.
- Nội dung thay đổi làm stale explanation.

### M9.6: Chat AI trong lesson bằng RAG

Mode: UI + API

Mục tiêu:

- Student chat với AI theo tài liệu buổi học.
- Chapter chỉ là metadata tổng quan, không có context RAG riêng ở MVP.

Phạm vi:

- Chat session/messages.
- Retrieval theo lesson.
- Gửi một số tin nhắn gần nhất, không gửi toàn bộ lịch sử.
- Không cho học sinh upload ảnh/file trong chat.
- User-upload trong chat nếu làm ở version sau phải là chat attachment riêng, lưu object storage theo user/session/message với quota/rate limit/quyền truy cập riêng; không đưa vào OCR artifact cache của tài liệu nguồn.
- Nếu học sinh hỏi về hình/bảng/sơ đồ/trang cụ thể trong lesson, backend có thể tự lấy page image/crop từ PDF gốc làm visual context cho model vision theo budget/rate limit.
- Khi học sinh hỏi theo số trang in, backend phải resolve qua `printedPage` trong page metadata/image manifest trước khi chọn PDF page/crop. Nếu mapping thiếu hoặc mơ hồ, trả fallback rõ ràng hoặc hỏi lại.
- Từ chối câu hỏi ngoài phạm vi lesson.

Done khi:

- Chat lưu lịch sử.
- AI không trả lời ngoài context lesson.
- Câu hỏi về hình/trang trong tài liệu có đường lấy visual context từ PDF gốc hoặc fallback rõ ràng nếu chưa bật visual model.

### M9.8: Admin AI generation panel UI

Mode: UI + API

Mục tiêu:

- Admin có UI gọi các job AI tạo nội dung trong màn chi tiết buổi học `/admin/lessons/[lessonId]`.

Phạm vi:

- Panel generate summary cho đúng `lessonId` hiện tại.
- Panel/nút generate quiz/flashcard/test cho đúng `lessonId` hiện tại.
- Hiển thị precondition theo buổi học: đã có OCR/chunks, embedding/retrieval sẵn sàng và content schema/editor tương ứng.
- Job status polling.
- Preview output.
- Link sang editor/review flow nếu đã có.
- Không gọi AI trực tiếp từ frontend; frontend chỉ gọi API/job.
- Không đặt action sinh AI ở cấp course/chapter như thể sinh từ toàn bộ sách; mọi generate trong MVP là theo từng buổi học.

Done khi:

- Admin bấm generate từ UI và thấy trạng thái job.
- Output AI hiển thị ở nơi admin có thể review/sửa theo flow hiện có.
- Các nút generate dùng current `lessonId`, không cho sinh nhầm bằng context toàn khóa hoặc lesson khác.
