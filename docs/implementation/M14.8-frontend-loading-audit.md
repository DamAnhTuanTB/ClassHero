# M14.8 Frontend loading, prefetch và transition audit

Ngày rà soát: 2026-07-29

Phạm vi: toàn bộ 13 route hiện có trong `apps/web/app`, gồm Public/Auth, Admin và
Student. Task này chỉ thay đổi front-end; không đổi API/database hay nghiệp vụ.

## 1. Nguyên tắc áp dụng

- Data `critical` được gọi ngay khi đủ route ID và session, không chờ người dùng
  bấm tab.
- Data `near-next` chỉ được prefetch khi có khả năng dùng sớm; cache key có scope
  domain/role/user và có `staleTime` rõ ràng.
- Editor, media tool và dialog nặng thuộc `optional-heavy`, tiếp tục lazy-load và
  chỉ warm-up khi trình duyệt nhàn hoặc người dùng thể hiện intent.
- Request nhanh dưới 300 ms không dựng skeleton. Nếu skeleton đã xuất hiện thì
  giữ tối thiểu 300 ms để tránh lóe một frame.
- Mỗi list/detail/tab dùng skeleton riêng bám layout đích. Chỉ dùng chung primitive
  hình học nhỏ và hook điều phối thời gian.
- Background refetch giữ data cũ; mutation chỉ pending/disabled tại control liên
  quan, không thay toàn màn bằng loading.

## 3. Request count trước và sau

| Luồng                               | Trước                                                          | Sau                                                                                         |
| ----------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Student lesson, mở tab Quiz lần đầu | Status Quiz có thể bắt đầu khi click; UI phía dưới lóe loading | Status Quiz bắt đầu trước click; đổi tab không tăng request và không mount transient loader |
| Admin lesson, mở Flashcard lần đầu  | 2 request sau click: sets + cards                              | 0 request mới lúc click khi idle prefetch hoàn tất; tổng mỗi endpoint vẫn là 1              |
| Course list → detail                | Detail bắt đầu sau navigation                                  | Hover/focus/touch hoặc course có xác suất mở cao warm cache trước navigation                |
| Background refetch list/detail      | Có nguy cơ quay về loading nếu dùng chung `isFetching`         | Giữ data cũ; chỉ initial load mới đủ điều kiện hiện skeleton                                |

Prefetch Admin lesson có thể thêm tối đa request metadata/content của Quiz,
Flashcard và Test sau khi critical lesson đã render. Đây là warm-up có giới hạn,
không chặn first paint và không áp dụng cho Documents/editor/media nặng.

## 4. Cấu trúc triển khai

- Query-option factories nằm tại hook domain Quiz/Flashcard/Test/course để page
  owner và prefetch dùng cùng key/query function.
- `use-admin-lesson-content-prefetch.ts` điều phối warm-up của lesson workspace,
  không chuyển API ownership vào component UI.
- `use-stable-loading-visibility.ts` chỉ chia sẻ chính sách thời gian; hình học
  skeleton vẫn nằm local trong từng screen/panel.
- Course cards phát tín hiệu intent qua callback; card không biết query client hay
  API cụ thể.

## 5. Regression gate

- TypeScript: `pnpm --filter web typecheck`.
- Targeted ESLint cho toàn bộ file web/test thay đổi.
- Playwright desktop + mobile:
  - Student Quiz status được preload trước tab click.
  - Admin Flashcard sets/cards được preload trước tab intent.
  - Đổi tab không mount transient loading và không tạo request thừa.
- Production build dùng webpack theo cấu hình hiện tại của repo.
