## M3: Admin learning path, chapter và lesson CRUD

### M3.1: Admin learning path API

Mode: API only

Mục tiêu:

- Admin quản lý lộ trình học.

Phạm vi:

- CRUD learning path.
- Publish/archive/hide status.
- Price/original price/discount price fields.
- Subject/grade filtering.
- Audit log cho thao tác quan trọng.

Done khi:

- Admin tạo/sửa/xóa mềm/publish lộ trình.
- Student chỉ thấy lộ trình published.

### M3.2: Admin chapter và lesson API

Mode: API only

Mục tiêu:

- Admin quản lý chương học tùy chọn và buổi học có/không thuộc chương trong lộ trình.

Phạm vi:

- CRUD chapter.
- CRUD lesson.
- Create lesson trực tiếp theo learning path với `chapterId` optional/nullable; endpoint nested theo chapter được giữ để tương thích.
- Move lesson tới bất kỳ vị trí nào trong cùng chapter, chapter khác hoặc top-level; top-level cho phép chapter và lesson xen kẽ.
- Completion guard chặn kết quả move đặt lesson trước bất kỳ lesson khác đã có ít nhất một học sinh hoàn thành; response admin trả cờ aggregate để UI khóa drop target.
- Lesson có loại `BASIC | LIVE`, mặc định `BASIC`; `liveUrl` optional và chỉ được lưu cho lesson `LIVE`.
- Chapter overview/objectives/status.
- Sort order.
- Create chapter/lesson không nhận order từ client; backend tự append cuối container, kiểm tra và lưu thứ tự liên tục trong transaction. Move/reorder dùng endpoint riêng.
- `exam_open_at` hoặc thời điểm mở bài thi.
- Video link.
- Completion criteria default score >= 7.
- Lesson status/publish nếu đã chốt.

Done khi:

- Admin tạo được khóa chỉ có lesson, khóa chỉ dùng chapter và khóa kết hợp cả lesson không thuộc chương lẫn chapter.
- Logical order top-level của chapter và lesson không thuộc chapter không bị trùng; lesson trong chapter có order riêng theo chapter.
- Tên lesson active không bị trùng trong cùng nhóm đích; các chapter/nhóm khác nhau có thể dùng cùng tên lesson.
- API create/get/update lesson lưu và trả đúng `lessonType`, `liveUrl`; đổi về `BASIC` phải clear `liveUrl`.
- Chapter không có video/tài liệu/PDF/quiz/flashcard/test riêng.

### M3.3: Public/student learning path listing

Mode: API only

Mục tiêu:

- Học sinh/phụ huynh xem danh sách lộ trình published.

Phạm vi:

- Public/student route xem danh sách lộ trình.
- Group/filter theo grade.
- Ưu tiên lớp của học sinh nếu đã đăng nhập.
- Course detail summary.

Done khi:

- Student lớp 7 thấy Toán 7 ưu tiên.
- Chưa mua vẫn xem được thông tin lộ trình.

### M3.4: Admin learning path/chapter/lesson UI cơ bản

Mode: UI + API

Mục tiêu:

- Có giao diện admin tối thiểu để nhập dữ liệu lộ trình/chương học/buổi học.

Phạm vi:

- List/create/edit learning path.
- Modal create/edit learning path có `Ngày bắt đầu` và `Ngày kết thúc` tùy chọn (date-only); nếu nhập cả hai, ngày kết thúc không được sớm hơn ngày bắt đầu.
- Modal create/edit learning path có khoảng `Số buổi học từ`/`Số buổi học đến` tùy chọn (1-500); đây là số buổi dự kiến, không phải counter lesson thực tế, và giá trị đến không được nhỏ hơn giá trị từ.
- List/create/edit chapter trong learning path detail.
- List/create/edit lesson.
- Modal chapter/lesson không có field thứ tự; backend tự xếp cuối khi tạo, còn thay đổi vị trí dùng cây kéo-thả hoặc action `Di chuyển`.
- Header `Cấu trúc khóa học` có hai action ngang hàng `Thêm chương` và `Thêm buổi học`; empty state đầu tiên có đủ hai CTA.
- Header tạo lesson top-level; action trong chapter tạo lesson vào chapter tương ứng. Admin có thể đổi container bằng action `Di chuyển` sau khi tạo.
- Cây cấu trúc cho phép chapter và lesson top-level xen kẽ; drag/drop lesson giữa mọi container/vị trí hợp lệ, kèm action move thay thế cho mobile/keyboard.
- Move option vi phạm mốc lesson đã có học sinh hoàn thành bị disabled; drag/drop chạy preflight và từ chối bằng thông báo. Conflict stale từ API phải refetch và báo rõ.
- Lesson create/edit modal có select `Loại buổi học` gồm `Học cơ bản` và `Học live`, mặc định `Học cơ bản`; field `Link học live` optional chỉ hiển thị khi chọn `Học live`.
- Lesson detail có action `Chỉnh sửa buổi học`; action này phải lazy-load và tái sử dụng đúng lesson create/edit modal của course detail, nạp dữ liệu lesson hiện tại, lưu qua cùng mutation rồi refresh metadata tại lesson detail.
- Tab `Tài liệu` tại lesson detail phải lazy-load và tái sử dụng nguyên nhóm field `Tài liệu nền tảng`, `Tài liệu bổ sung`, `Bài tập về nhà` của modal lesson; dữ liệu và mutation dùng chung để upload/xóa/sắp xếp/lưu không lệch giữa hai nơi.
- Lesson create/edit modal có chỗ gán khoảng trang tùy chọn từ source document nếu course đã upload tài liệu nguồn trước đó; admin vẫn có thể chỉ lưu metadata buổi học trước. Phần nhập trang dùng API/page status của M4.x, có preview trang/text ngắn và phải disabled khi tài liệu nguồn chưa xử lý xong hoặc còn trang cần xác nhận.
- Modal tạo lesson có phần tài liệu tham khảo tùy chọn: admin bấm `Thêm tài liệu` để thêm nhiều dòng, mỗi dòng gồm tên hiển thị và file PDF. Các file này lưu kèm lesson dạng storage-only, không chạy OCR/chunking.
- Form validation.
- API integration bằng TanStack Query.
- Search, filter và sort của danh sách quản trị được đồng bộ vào URL để giữ nguyên sau refresh/F5.

Done khi:

- Admin thao tác được từ UI và có thể tạo lesson đầu tiên khi khóa chưa có chapter.
- UI không thay thế backend permission.
- Student course detail đánh số chương tuần tự theo riêng danh sách chapter, không dùng vị trí top-level có lesson xen kẽ và không tự ghép tiền tố `Chương {n}.` vào title do admin nhập.

### M3.5: Public/student course browsing UI

Mode: UI + API

Mục tiêu:

- Có UI public/student để xem lộ trình học và chi tiết lộ trình.

Phạm vi:

- Student course browsing làm trước theo quyết định hiện tại.
- Student course list.
- Search và filter course list được đồng bộ vào URL để giữ nguyên sau refresh/F5.
- Student course detail với enrollment/trial state nếu API đã có.
- Student course detail render đúng `structureItems` xen kẽ; khóa không có chapter vẫn học/điều hướng lesson bình thường theo thứ tự cây.
- Public landing page, public course list và public course detail tạm hoãn sang pass sau; route public hiện chỉ cần không bị gãy điều hướng cơ bản nếu đang có.
- CTA đăng nhập/đăng ký/học thử/mua lộ trình; payment thật nối ở `M8.4`.

Done khi:

- Student xem được course list/detail từ UI.
- User chưa đăng nhập xem được lộ trình published khi public pass được mở lại.
- CTA không hard-code quyền; backend/payment vẫn xử lý ở task sau.

### M3.6: Personal learning path clone foundation

Mode: Worker/Integration

Mục tiêu:

- Tạo private fork của khóa đã mua cho đúng một enrollment mà không biến fork thành sản phẩm mới.

Phạm vi:

- Prisma migration cho `LearningPathKind`, source lineage và `Enrollment.deliveryLearningPathId`.
- Clone service idempotent, BullMQ job/status và rollback an toàn.
- Deep-copy cấu trúc/nội dung quản trị mutable; reuse file R2/OCR artifact bất biến.
- Admin create/get API và audit log; không có revert về khóa gốc sau activation.
- Enrollment chỉ chuyển sang bản cá nhân sau khi clone hoàn tất.

Không làm:

- Không tự đồng bộ thay đổi tương lai từ khóa gốc.
- Không tạo nhiều bản cá nhân active cho một enrollment.
- Không làm group/cohort curriculum trong task này.
- Không làm API/UI quay lại khóa gốc sau khi bản cá nhân đã activation.

Done khi:

- Clone thành công tạo private path độc lập, clone lỗi không đổi lộ trình đang học.
- Bản cá nhân không xuất hiện trong catalog và không thể purchase/enroll trực tiếp.
- Edit bản cá nhân không thay đổi khóa gốc.
- Không gọi paid OCR lại khi artifact/cache hiện có hợp lệ.

### M3.8: Admin lesson video transcript

Mode: UI + API

Mục tiêu:

- Admin lấy caption công khai của video YouTube, duyệt/chỉnh sửa và lưu thành transcript theo thời gian của buổi học.

Phạm vi:

- API admin best-effort lấy transcript công khai từ video YouTube của lesson; ưu tiên tiếng Việt, fallback sang ngôn ngữ công khai phù hợp và chỉ trả các đoạn nằm trong khoảng phát thực tế sau khi áp dụng cấu hình cắt đầu/cuối.
- Không dùng YouTube Data API để tải caption của video bên thứ ba và không chạy speech-to-text khi video không có caption.
- Lưu transcript đã duyệt trong `customVideoSettings` dưới dạng danh sách `{ time, endTime?, text }` theo timestamp nguồn để vẫn ánh xạ đúng khi cấu hình cắt thay đổi; API bản nháp và form admin quy đổi sang trục phát sau cắt bắt đầu tại `0:00`.
- Giữ nguyên cue caption nguồn theo `offset`/`duration` YouTube trả về; không chia lại thành bucket cố định hoặc ước tính timestamp từng từ.
- Panel transcript ở lesson detail, lấy cảm hứng từ YouTube: tìm kiếm, header chapter kèm timestamp tại đúng vị trí, danh sách theo thời gian, chỉnh mốc/nội dung, phát video ngay từ mốc của từng đoạn, highlight và auto-scroll theo đoạn đang phát, rồi lưu.
- Có loading, empty, error, disabled state; lấy lại transcript không tự ghi đè bản đã lưu trước khi admin bấm lưu.
- Hỗ trợ responsive và theme sáng/tối.

Done khi:

- Admin lấy được toàn bộ caption công khai thuộc khoảng phát thực tế của video mẫu, sửa và lưu lại được; đoạn bị cắt khỏi đầu/cuối không xuất hiện.
- Transcript lấy mới giữ timestamp cue với tối đa 3 chữ số thập phân và độ dài đoạn không cố định; bấm phát một đoạn phải dùng đúng `offset` đó.
- Admin bấm action phát ở một đoạn transcript thì player cộng phần cắt đầu để tua đến đúng mốc nguồn, bắt đầu phát và được đưa vào vùng nhìn.
- Khi player vượt qua mốc transcript, chỉ đoạn tương ứng chuyển sang trạng thái `Đang phát`; panel tự cuộn trong container tới đoạn đó mà không làm cuộn toàn trang hoặc re-render theo mỗi tick thời gian.
- Active transcript được xác định bằng khoảng cue gốc `[time, endTime)`; khi nhiều cue chồng nhau thì cue bắt đầu mới nhất được active để focus không chậm một nhịp.
- Sau khi admin lưu thay đổi tên hoặc thời gian chapter, header chapter trong panel transcript cập nhật ngay theo dữ liệu lesson mới mà không cần tải lại trang và không làm mất nội dung transcript đang chỉnh sửa.
- Video không có caption trả thông báo rõ ràng, không làm hỏng phát video và không xóa transcript đang có.
- API yêu cầu `ADMIN`, validate giới hạn/sắp xếp dữ liệu transcript; web/api typecheck và test tập trung đều qua.

### M3.9: Catalog lĩnh vực và đối tượng hướng đến khóa học

Mode: UI + API

Mục tiêu:

- Admin quản lý catalog Lĩnh vực; khóa học chọn Lĩnh vực và đúng một Đối tượng hướng đến thay cho enum Môn học/field Lớp cố định.

Phạm vi:

- CRUD Lĩnh vực tại `/admin/domains`.
- Kéo-thả sắp xếp thứ tự Lĩnh vực tại `/admin/domains` theo cùng pattern của chương/buổi học; thứ tự được lưu bằng `domains.sort_order` và dùng làm ưu tiên hiển thị khóa học theo lĩnh vực.
- Seed Lĩnh vực Toán, Vật lý, Hóa học, Tiếng Anh.
- Seed Đối tượng hướng đến: Khối 3 đến Khối 12, Khối Tiểu học, Khối THCS,
  Khối THPT, Toàn khối và Người đi làm.
- Migration backfill khóa học cũ theo lĩnh vực/khối tương ứng.
- Modal tạo/sửa khóa học lấy option động từ catalog và dùng single select cho Đối tượng hướng đến.
- Bộ lọc danh sách khóa học Admin lấy đầy đủ Lĩnh vực và Đối tượng hướng đến từ
  cùng catalog động, lọc theo `domainId` và `targetAudienceId`.
- Bộ lọc màn student Khám phá lấy option động từ cùng catalog; nhãn hiển thị phía student vẫn là `Khối lớp` và `Môn học`.

Done khi:

- Admin thêm/sửa/xóa được Lĩnh vực chưa dùng; lĩnh vực đang dùng không thể bị xóa.
- Admin đổi được vị trí Lĩnh vực và thứ tự vẫn được giữ sau khi tải lại; khóa học mặc định được xếp theo thứ tự Lĩnh vực trước, rồi theo `learning_paths.sort_order`.
- Tạo/sửa khóa học bắt buộc chọn Lĩnh vực và đúng một Đối tượng hướng đến. API tiếp tục dùng mảng `targetAudienceIds` và bảng nối để tương thích dữ liệu cũ, nhưng contract ghi mới chỉ nhận đúng một ID.
- Student thấy đầy đủ Đối tượng hướng đến và Lĩnh vực do admin cấu hình theo đúng `sortOrder`, không dùng danh sách khối/môn hard-code.
- Khi `Khối lớp = Tất cả`, Student hiển thị lần lượt khóa đã mua, khóa phù hợp với học sinh, rồi các nhóm Khối 12→10, toàn khối THPT, Khối 9→6, toàn khối THCS, Khối 5→3, toàn khối Tiểu học, toàn khối học sinh và Người đi làm; nhóm rỗng được ẩn. Khóa đã mua bị loại khỏi toàn bộ nhóm phía dưới; khóa phù hợp vẫn được lặp lại trong nhóm đối tượng tương ứng và mỗi card chỉ mang nhãn của chính đối tượng đang làm nó xuất hiện.
